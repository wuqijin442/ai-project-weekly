## 本周趋势解读

### 1. 「技能层」拿走了一半的增量

| 项目 | 本周 🔺 | 技能层角色 |
| --- | --- | --- |
| reverse-skill (#1) | 9,635 | 垂直领域技能路由包 |

| google/skills (#10) | 1,143 | 厂商官方技能库 |

**四席合计 🔺22,895，占 Top 10 总增量的 50.2%。** 如果只算纯技能包三席（#1/#6/#10），也有 🔺14,849 / 32.5%。

更值得记的是这四家**不在同一个位置上竞争**：reverse-skill 卖的是垂直手艺，google/skills 卖的是自家产品线的独家知识，book-to-skill 干脆不卖技能、卖**造技能的机床**，TencentDB 则把技能当成可治理的团队资产来管。08-08 日报里说「技能层要独立于 Agent 本体存在」，本周进一步分化出了**供给侧的四种商业位置**。

### 2. reverse-skill：从「怎么写代码」到「怎么干某一行的活」

7 月以来的技能包冠军轮换（mattpocock → obra → addyosmani）始终没跳出通用软件工程。reverse-skill 是第一个以**专业领域纵深**登顶的——它要解决的不是「Agent 会不会写函数」，而是「Agent 懂不懂逆向分析的工序」。

这个转折的含义是：**技能包的护城河从「工程品味」换成了「领域 know-how」**。前者可被更好的模型抹平，后者不能。可以预期后续会有更多垂直技能包出现（安全之后大概率是数据合规、芯片验证、生物信息这类高门槛领域）。

需要留意的边界：它的 `RULES` 层把 scope gate 放在 ACT 之前——**授权范围先确认再执行**。做安全类技能包，这既是合规底线，也是产品设计上跟通用技能包最大的结构差异。

### 3. 本地推理双雄：airllm 与 ds4 从两端夹击同一个前提

| | [[lyogavin_airllm\|airllm]] (#4) | [[antirez_ds4\|ds4 / DwarfStar]] (#9) |
| --- | --- | --- |
| 本周 🔺 | 5,711 | 1,254 |
| 解决的问题 | 显存**不够**也要跑 | 高内存机器上跑得**又快又稳** |
| 手段 | 分层推理 + 稀疏 MoE 专家流式加载 | 窄而深的原生引擎，全链路一起构建测试 |

| 协议 / 语言 | Apache-2.0 / Python | MIT / C |

两者共同的前提是**开放权重模型已经装得进个人硬件**。airllm 走的是「不量化、不蒸馏、不剪枝，靠调度换空间」；ds4 明确说自己**不是通用 GGUF runner**——模型加载、prompt 渲染、工具调用、KV 状态、HTTP 服务、编码 Agent 全部一起构建一起测，宁可窄也要稳。

> 📌 **与本地基建直接相关**：ds4 的 CUDA 后端 README 里点名支持 **DGX Spark**，另有 Metal（96GB+ Mac）与 ROCm（Strix Halo / Framework Desktop）路径；多机可用流水线并行叠加内存跑更大模型。手上有 DGX Spark 的话，这是本周最值得实测的一个。
