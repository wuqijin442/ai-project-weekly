## 5. 开放问题 / 值得关注的风险

1. **实测通过率极低（1/5 success）**：5 个项目中 4 个实测 failed/skipped，需区分是"项目本身部署复杂"还是"采集环境配置问题"。建议对 failed 项补充 Docker / 依赖版本日志，避免误判项目质量。
2. **多 Agent 框架的可靠性天花板**：TradingAgents 与 security-audit-skill 都依赖多阶段 LLM 调用，单步幻觉会级联放大。当前缺乏统一的"Agent 编排可观测性"标准，值得跟踪 OpenTelemetry for LLM 等方向。
3. **本地 AI 的硬件门槛**：VoiceStudio 宣称"fully local"，但语音克隆模型（如 VALL-E、CosyVoice 级别）对 GPU 显存要求不低；需确认其最低硬件规格，否则"本地化"对多数开发者仍是纸面能力。
4. **AI 安全审计的对抗性局限**：security-audit-skill 用 LLM 做安全审计，但 LLM 本身可能被 prompt injection 绕过；"用 AI 审 AI 写的代码"存在同分布盲区，需结合传统 SAST/DAST 工具交叉验证。
5. **历史知识库断裂**：如第 3 节所述，近 70 天的历史摘要全部缺失，知识图谱无法形成时间轴。这是流程/工具层面的系统性风险，优先级高于任何单个项目的跟进。
