> 针对 09-13 自动化运行时发现的两处环境异常（托管 Python 损坏 / 沙箱 git 联网失败）进行根治。

## 一、托管 Python 3.13.12（标准库被掏空）

**根因**：`C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/Lib/` 目录整体缺失（含 `encodings/`），导致任何 `import` 报 `Failed to import encodings module`；`DLLs/` 中 `_sqlite3.pyd` 等扩展模块亦缺失。exe 实际为 nightly 构建 `3.13.14 (main, Jun 11 2026)`。

**修复动作**：
1. 从 `https://www.python.org/ftp/python/3.13.12/python-3.13.12-embed-amd64.zip` 下载 embeddable 包；
2. 解包其内 `python313.zip` 的标准库，还原 541 个文件到 `Lib/`；
3. 补齐缺失扩展模块 `_sqlite3.pyd` / `winsound.pyd` / `sqlite3.dll` 到 `DLLs/`。

**验证**：
- `python -c "import encodings, ssl, urllib.request, json, sqlite3, zipfile, subprocess, hashlib"` → OK
- 真实 HTTPS：`urllib.request.urlopen('https://api.github.com/rate_limit')` → HTTP 200
- 子进程调起 git：`subprocess.run(['git','--version'])` → `git version 2.55.0.windows.3`，rc=0
- 当前分支识别：`win`，rc=0

## 二、沙箱 git（libcurl-4.dll 缺失，联网失败）

**根因**：WorkBuddy 托管 PortableGit `versions/1.2.0/mingw64/bin/` 缺少 `libcurl-4.dll` 及 100+ 依赖库（PATH 首位即此损坏 git），任何 https/ssh 推拉均报 `failed to load library 'libcurl-4.dll'`；且该 PortableGit 未配置凭据助手，plain push 会卡在 Username 提示。

**修复动作**：
1. 从系统 `C:/Program Files/Git/mingw64/bin/` 复制全部缺失文件（115 个：含 `libcurl-4.dll`、`git-remote-https.exe` 及依赖链）到 PortableGit bin；
2. 在全局 `~/.gitconfig` 增加 `[credential] helper = manager`，使 GCM（已随文件复制到位）从 Windows 凭据管理器提供缓存 PAT。

**验证**：
- `git ls-remote https://github.com/octocat/Hello-World.git` → rc=0（纯网络）
- `git -C E:/AI_Project_Weekly fetch origin win` → rc=0（GCM 提供凭据）
- 托管 Python 子进程内调 git 全部 rc=0
